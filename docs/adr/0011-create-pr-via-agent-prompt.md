# 0011. 状态条 [创建 PR] 直接派发 agent 会话创建，不再弹预填面板

- 状态：Accepted
- 日期：2026-08-14

## 上下文

design §6 原将"创建 PR"定为零模型回合：宿主用 commit 记录确定性推导标题/描述（`prDraft`），前端弹出预填面板由用户确认后调 `createPr`。线上验收（ADR-0010 同一轮）反馈了两点：

1. 面板要求用户确认标题/描述，与"agent 已掌握全部上下文"的体验相悖——用户期望一键创建，标题与描述由模型归纳。
2. 确定性推导只有 commit 文本可用，归纳质量明显低于模型基于会话上下文的归纳；"零模型回合"在这一步不是收益。

另外状态条容器撑满了会话列宽（纯样式问题，与本决策无关，一并修复但不入 ADR）。

## 决策

[创建 PR] 变为单击动作：通过 `shell.prompt` 向当前会话派发一条创建指令，由模型经 GitHub 工具（`github_pr_create`，幂等由 ADR-0004 兜底）自行归纳标题/描述并创建。按钮随即进入 loading（禁用 + "创建中…"），由 flow-state 轮询在状态离开 `pr-ready` 时自然结束；超时（默认 180 s，可注入）恢复按钮并提示查看会话。宿主的 `prDraft` / `createPr` `@Remote` 方法与 pr-draft 派生逻辑原样保留——API 面不变，供其他集成方与非会话路径使用。

## 备选方案

- **保留面板、默认收起**：仍要求用户确认，没有解决体验诉求。
- **宿主用 `prDraft` 自动填充后直接调 `createPr`**：仍是 commit 文本拼接，标题质量不变，且用户已明确要模型归纳。
- **模型侧新增"展示创建进度"工具**：把 UI 控制权交给模型，ADR-0002 已论证过不可取。

## 后果

- 创建 PR 现在花费一个模型回合，与 [AI review] 同路径——这是有意的取舍（质量优先于回合成本）。
- 面板（标题/描述输入、预填、草稿状态）连同其 i18n 字符串与样式删除；`sameFlowState` 驱动的轮询新增"创建中快轮询"（badge 节奏、不退避、超时封顶，存活期短暂故不做页面隐藏暂停）。
- loading 的结束依赖轮询，最长滞后一个轮询周期；agent 失败或用户取消时由超时兜底恢复。
- design §6 的"创建 PR：模型参与=否"同步改写为"是"。
