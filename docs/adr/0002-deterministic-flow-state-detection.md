# 0002. 用确定性 git 检查而非 AI 判断驱动 PR 状态条

- 状态：Accepted
- 日期：2026-08-13

## 上下文

PR 状态条需要在"agent 完成了阶段性工作"时出现。"阶段性成功"若交给模型判断，会产生 token 成本，且存在"AI 觉得完成了但实际没有提交"的误报可能。

## 决策

宿主监听 agent 回合结束事件，只跑廉价的确定性 git 检查（分支是否领先 base、本回合是否有新提交、head 分支是否已有开放 PR 及其 CI conclusion），归纳为四态状态机通过 `github/flow-state` 事件推给前端。模型完全不参与触发。

## 备选方案

- **让模型自报"任务完成"**：消耗 token，且信号主观、不可复验。
- **让模型主动调用某个"展示状态条"工具**：把 UI 控制权交给模型，回放与降级路径都难以保证一致。

## 后果

- 零 token 成本；触发条件客观可测（fixture git 仓库即可覆盖全部状态迁移）。
- 只对"已提交"的工作生效：未 commit 的改动不会触发状态条——这是有意的行为边界，不是缺陷。
- 宿主需要依赖回合结束事件与本地 git 可用性；非 git 仓库/remote 非 GitHub 时静默隐藏。
